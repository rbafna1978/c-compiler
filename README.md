# tensor-lang

A small compiler, from scratch, for a C-like language with **statically shape-checked tensors**,
**reverse-mode automatic differentiation**, and **its own fusion and tiling optimizations** —
lexer → parser → sema → LLVM codegen → optimizer, all hand-written, emitting real LLVM IR and
linking to a native binary via clang.

```c
float loss(tensor<float, 2, 1> W, float b, tensor<float, 4, 2> x, tensor<float, 4, 1> y) {
  tensor<float, 4, 1> err = matmul(x, W) + b - y;
  return sum(err * err);
}

int main() {
  tensor<float, 2, 1> W;  // trained by hand-rolled gradient descent, in this language
  float b = 0;
  for (int step = 0; step <= 200; step += 1) {
    tensor<float, 2, 1> dW = grad(loss, 0, W, b, x, y);  // reverse-mode AD, not finite differences
    float db = grad(loss, 1, W, b, x, y);
    W -= dW * 0.02;
    b -= db * 0.02;
  }
}
```

That example is [`tests/integration/test_programs/grad_train.c`](tests/integration/test_programs/grad_train.c)
— it compiles, runs, and its loss goes from 48.75 to 0.0016 over 200 steps of gradient descent
generated entirely by this compiler.

## What's actually novel here

Lexer → parser → sema → codegen is a common project; the parts below are not:

1. **Shapes are checked at compile time.** `matmul` of a `tensor<float,2,3>` and a
   `tensor<float,2,2>` is a compile error *before codegen runs*, with the shapes in the message —
   not a runtime crash. See [`src/sema/sema.cpp`](src/sema/sema.cpp).
2. **`grad(f, i, args...)` is a real compiler transform, not a library.** It differentiates a
   function by rewriting its AST into a new function's AST (forward pass + reverse-order adjoint
   statements), which then goes through the same sema and codegen as everything else. See
   [`src/autodiff/autodiff.cpp`](src/autodiff/autodiff.cpp) and
   [`docs/DESIGN.md`](docs/DESIGN.md#autodiff-correctness) for why it's correct.
3. **Two working optimizations of our own**, on top of (not instead of) LLVM's standard `-O2`
   pipeline: an AST-level operator-fusion pass, and a cache-blocked matmul. Both are switchable
   (`--no-fuse`, `--no-tile`) so they could be benchmarked against themselves, not just asserted to
   help — see [Benchmarks](#benchmarks) and [`docs/DESIGN.md`](docs/DESIGN.md#fusion-correctness)
   for why fusion doesn't change int/float promotion order.

## Benchmarks

Generated by [`benchmarks/run_benchmarks.py`](benchmarks/run_benchmarks.py); full numbers and
methodology in [`BENCHMARKS.md`](BENCHMARKS.md).

| Benchmark | This compiler's optimization | Baseline (same compiler, flag off) | Speedup |
|---|---|---|---|
| matmul, 512×512 float | tiled (32×32 blocks) | naive triple loop | **1.53x** |
| elementwise chain, 2M elements | fused (one loop) | unfused (one loop per operator) | **2.83x** |

Both rows are checked byte-identical in output before being timed — the optimization changes
speed, never the result. `BENCHMARKS.md` also has honest context numbers against clang `-O2` (we
tie on quicksort, lose on recursive fibonacci) and NumPy's BLAS (~1500x faster on matmul, as
expected from a non-vectorized, single-threaded loop nest) — included because a number without a
loss anywhere is not a number to trust.

## Language reference

| Feature | Example |
|---|---|
| Scalars | `int`, `float`, `char`, `void`, `struct S { int x; }` |
| Control flow | `if`/`else`, `while`, `for`, functions, recursion |
| Tensor type | `tensor<float, 2, 3>` — element type + static dimensions |
| Tensor literal | `[[1, 2, 3], [4, 5, 6]]` |
| Elementwise ops | `+ - * /` (same shape; a scalar broadcasts), unary `-`, `+=` etc. |
| Builtins | `matmul(A, B)`, `transpose(A)`, `sum(A)`, `exp`/`log`/`tanh` (elementwise) |
| Indexing | `A[i]` (drops the leading dimension), `A[i][j] = x` |
| Autodiff | `grad(f, i, args...)` — gradient of scalar-returning `f` w.r.t. its `i`-th parameter |
| I/O | `print(x)` — numbers, strings, and tensors (one row per line) |

`grad`'s function must be *straight-line*: declarations with initializers, then one `return`. Loops
and branches inside the differentiated function itself aren't supported (using its gradient inside
a loop, as the training example above does, is fine) — see why in
[`docs/DESIGN.md`](docs/DESIGN.md#autodiff-correctness).

## Architecture

```
source.c
  │  src/lexer  (flex)          tokens
  ▼
  │  src/parser (bison, LALR)   AST                      src/ast/ast.h
  ▼
  │  src/sema                   type-checked AST          (adds ASTNode::expr_type
  ▼                                                          on every node)
  │  src/autodiff                grad(...) calls rewritten into generated
  ▼                              __grad_f_i AST functions, then re-checked by sema
  │  src/codegen                LLVM IR (tensors: flat row-major storage;
  ▼                              fusion/tiling decided here, not as a separate pass)
  │  src/optimizer               LLVM's standard -O2 pipeline (PassBuilder)
  ▼
  │  clang                      native executable
  ▼
 a.out
```

Each stage is a normal visitor over the same `ast::ASTNode` tree
([`src/ast/ast.h`](src/ast/ast.h)); `autodiff` and `codegen` both build/consume that tree rather
than a separate IR, which is what makes the "differentiate by rewriting the AST" approach in point
2 above workable without a second compiler front end.

## Build & test

```bash
brew install cmake llvm@17 bison googletest
export PATH="$(brew --prefix bison)/bin:$PATH"
export CMAKE_PREFIX_PATH="$(brew --prefix llvm@17):$(brew --prefix googletest)"
cmake -S . -B build && cmake --build build -j"$(sysctl -n hw.ncpu)"
ctest --test-dir build --output-on-failure   # 43 tests: unit + integration (plain and -O)
```

```bash
build/compiler tests/integration/test_programs/grad_train.c -o /tmp/train && /tmp/train
build/compiler --dump-ast some.c     # print the AST and stop
build/compiler --dump-grad some.c    # print the AST after autodiff (shows the generated __grad_* function)
build/compiler --emit-ir some.c      # print LLVM IR instead of linking
python3 benchmarks/run_benchmarks.py --runs 7   # regenerate BENCHMARKS.md (needs numpy)
```

CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) builds from scratch and runs all 43
tests plus a benchmark-harness smoke test on every push.

## Known limitations

- **Static shapes only.** No `tensor<float, N, 3>` with a symbolic dimension.
- **`grad` differentiates straight-line functions only** (see above); a clear compile error names
  the line if the function isn't one.
- **Tensors above 16 KiB heap-allocate and are never freed** — fine for the short, run-once
  programs this project targets; a real service would need a per-call arena (noted as a
  `ponytail:` comment at the allocation site, [`src/codegen/codegen.cpp`](src/codegen/codegen.cpp)).
- **`float` is 32-bit**; gradient checks against a float64 NumPy oracle use a tolerance (1e-4 to
  2e-3 relative) rather than exact equality for that reason.
- **Fusion doesn't reach into `sum`/`matmul`.** `sum(a * b + c)` fuses `a * b + c` into one loop,
  then reduces it in a second loop — not one fused loop. A real gap, not chased here (see
  `docs/DESIGN.md`).
- **No SIMD or multi-threading.** The 1500x gap to NumPy's BLAS on matmul is expected, not a bug —
  see [Benchmarks](#benchmarks).
